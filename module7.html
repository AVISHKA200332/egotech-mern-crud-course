How the Browser Talks to the API

React is the client and Express is the server. React sends HTTP requests, Express processes them, and MongoDB stores the data. The response comes back as JSON and React uses that JSON to update the interface.

React
Collects input and shows the results.
Express
Validates, routes, and responds with JSON.
MongoDB
Stores the actual student records.

Create a Reusable Axios Client

A single API client keeps your requests organized. If the base URL changes later, you only update one file.

src/services/api.jsJS
import axios from 'axios';

const api = axios.create({
	baseURL: import.meta.env.VITE_API_URL || 'http://localhost:5000/api',
	headers: { 'Content-Type': 'application/json' },
});

export default api;

Enable CORS in Express

Browsers block requests from one origin to another unless the server explicitly allows it. That is what CORS solves.

backend/server.jsJS
const cors = require('cors');

app.use(cors({
	origin: ['http://localhost:5173', 'https://your-frontend.vercel.app'],
	methods: ['GET', 'POST', 'PUT', 'DELETE'],
}));
app.use(express.json());
If CORS is missing or misconfigured, the browser will fail the request even when the API route works in Postman.

Fetch Students with useEffect

Use useEffect to request data when the page loads. Keep loading and error states in React so the user knows what is happening.

src/pages/StudentPage.jsxJSX
import { useEffect, useState } from 'react';
import api from '../services/api';

export default function StudentPage() {
	const [students, setStudents] = useState([]);
	const [loading, setLoading] = useState(true);
	const [error, setError] = useState('');

	useEffect(() => {
		const loadStudents = async () => {
			try {
				const response = await api.get('/students');
				setStudents(response.data.students);
			} catch (err) {
				setError('Failed to load students.');
			} finally {
				setLoading(false);
			}
		};

		loadStudents();
	}, []);
}

Environment Variables

Keep local and production API URLs outside the codebase. Vite exposes variables that start with VITE_.

frontend/.envENV
VITE_API_URL=http://localhost:5000/api
Rule of thumb: never hardcode production URLs in components. Put them in an env file so you can switch environments without rewriting code.

Common Connection Problems

API not reachable
Check the backend port, server status, and base URL.
CORS error
Confirm the React origin is allowed in Express.
Empty response
Log response.data before rendering the list.
Env variable missing
Restart the frontend dev server after editing .env.
