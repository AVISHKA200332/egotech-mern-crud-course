What is Node.js? — Beginner Explanation

JavaScript normally only runs inside a web browser (Chrome, Firefox). Node.js is a runtime environment that lets JavaScript run on your computer — outside the browser, on the server side.

❌ Before Node.js

Servers were Python, PHP, Java, Ruby. Different language for front and back. Developers needed two skill sets.

✅ With Node.js

JavaScript runs everywhere — browser AND server. One language, full stack. That is why MERN is beginner-friendly.

Asynchronous & Non-Blocking

Node.js never waits. While waiting for a database query to finish, it handles other requests. This is why a single Node server can handle thousands of users simultaneously.

Sync vs Async — why async/await mattersJS
// ❌ Synchronous — blocks everything until done
const data = database.find();      // server FREEZES here
console.log(data);

// ✅ Asynchronous — does not block other requests
const getStudents = async () => {
  const students = await Student.find(); // waits but doesn't block
  console.log(students);
};

What is Express.js?

Node.js can handle HTTP requests but the raw code is verbose. Express.js is a minimal framework that wraps Node's HTTP module and makes it simple to define routes, add middleware, and send responses.

Raw Node.js vs Express.jsJS
// Raw Node.js HTTP — 8 lines to do what Express does in 3
const http = require('http');
const server = http.createServer((req, res) => {
  if (req.url === '/students' && req.method === 'GET') {
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify({ students: [] }));
  }
});

// Express — clean and readable
const app = express();
app.get('/students', (req, res) => {
  res.json({ students: [] });   // done!
});

server.js — The Entry Point

This is the first file Node.js runs. It connects the database, registers middleware, mounts routes, and starts listening for connections.

backend/server.jsJS
// ── 1. Load environment variables FIRST ──────────
require('dotenv').config();

// ── 2. Import packages ───────────────────────────
const express  = require('express');
const cors     = require('cors');
const mongoose = require('mongoose');

// ── 3. Create the Express app ────────────────────
const app = express();

// ── 4. Middleware (runs on EVERY request) ────────
app.use(cors());           // allow cross-origin requests from React
app.use(express.json());  // parse JSON request bodies

// ── 5. Import and mount routes ───────────────────
const studentRoutes = require('./routes/studentRoutes');
app.use('/api/students', studentRoutes);

// ── 6. Health-check route ────────────────────────
app.get('/', (req, res) => {
  res.json({ message: '🟢 API is running!', status: 'OK' });
});

// ── 7. 404 handler for unknown routes ────────────
app.use((req, res) => {
  res.status(404).json({ message: 'Route not found' });
});

// ── 8. Connect DB then start server ─────────────
const PORT = process.env.PORT || 5000;

mongoose
  .connect(process.env.MONGO_URI)
  .then(() => {
    app.listen(PORT, () => {
      console.log(`✅ MongoDB connected`);
      console.log(`🚀 Server → http://localhost:${PORT}`);
    });
  })
  .catch((err) => {
    console.error('❌ DB connection failed:', err.message);
    process.exit(1);
  });

// Export app so Jest can import it without starting server
module.exports = app;

Middleware — Beginner Explanation

Middleware are functions that run between a request arriving and your route handler executing. Think of it as an airport security line — every passenger (request) must pass through it first.

📱 Request
→
🔒 cors()
→
📋 json()
→
⚡ Route Handler
→
📤 Response

Custom Logger Middleware

Example custom middleware — add to server.jsJS
// Add BEFORE your route registrations
app.use((req, res, next) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
  next(); // ← CRITICAL: call next() or request hangs forever
});
Always call next() inside custom middleware unless you are sending a response. Forgetting it causes every request to hang with no response — a common beginner mistake.

Routes File

A route maps: HTTP Method + URL Path → Controller Function. Keep routes thin — just mapping, zero logic here.

backend/routes/studentRoutes.jsJS
const express = require('express');
const router  = express.Router();
const {
  getAllStudents,
  getStudentById,
  createStudent,
  updateStudent,
  deleteStudent,
} = require('../controllers/studentController');

// GET  /api/students      → list all
// POST /api/students      → create one
router.route('/').get(getAllStudents).post(createStudent);

// GET    /api/students/:id  → get one
// PUT    /api/students/:id  → update
// DELETE /api/students/:id  → delete
router.route('/:id').get(getStudentById).put(updateStudent).delete(deleteStudent);

module.exports = router;

const request = require('supertest');
const app     = require('../server');

describe('Health Check', () => {
  it('GET / should return 200 and status OK', async () => {
    const res = await request(app).get('/');
    expect(res.statusCode).toBe(200);
    expect(res.body.status).toBe('OK');
  });
});

Clean Code Tips — Express & Node

Separate routes from controllers

Routes only map URL + method to a function. All logic goes in the controller. This makes each file testable in isolation.

Every async function needs try/catch

Any function that calls await must be wrapped. Without it, an unhandled promise rejection crashes Node silently.

Return proper HTTP status codes

200 OK, 201 Created, 400 Bad Request, 404 Not Found, 500 Server Error. The frontend uses these to decide what to display.

Export app from server.js

module.exports = app at the bottom lets Jest import Express without starting the server on a port. Essential for testing.
