Concept

What is a REST API?

REST = a set of rules for how apps talk to each other

Imagine your React frontend is a customer in a restaurant. Your Express backend is the waiter. The API is the menu — it lists what the customer can order and how. REST is just a set of standard rules that everyone follows so apps know how to communicate. With REST, a GET request always means "give me data", a POST always means "create something new", and so on.

  • REST stands for Representational State Transfer
  • It uses standard HTTP methods (GET, POST, PUT, DELETE)
  • Data is sent and received as JSON
  • Each URL (called an endpoint) represents a resource (e.g. /api/students)
  • REST is stateless — the server doesn't remember previous requests
HTTP Methods

The 4 HTTP Methods = CRUD

Easy way to remember CRUD

Think of a notebook where you manage student records. You can Create a new entry (POST), Read existing entries (GET), Update a wrong entry (PUT), and Delete an entry (DELETE). These four actions cover everything a database needs to do.

HTTP MethodCRUD ActionURLWhat it doesStatus Code
GET Read all /api/students Get a list of every student in the database 200 OK
GET Read one /api/students/:id Get one specific student by their unique ID 200 OK
POST Create /api/students Add a new student (send data in the request body) 201 Created
PUT Update /api/students/:id Update an existing student's information by ID 200 OK
DELETE Delete /api/students/:id Permanently remove a student from the database 200 OK
Routes

Creating the Routes File

The routes file maps each URL + HTTP method to a controller function. Think of it as a switchboard — it receives the call and directs it to the right handler.

Create backend/routes/studentRoutes.js:

backend/routes/studentRoutes.js
const express = require('express');
const router = express.Router();

// Import all controller functions
const {
  getAllStudents,
  getStudentById,
  createStudent,
  updateStudent,
  deleteStudent,
} = require('../controllers/studentController');

// Define routes — each line = one API endpoint
router.get('/', getAllStudents);          // GET  /api/students
router.get('/:id', getStudentById);      // GET  /api/students/:id
router.post('/', createStudent);         // POST /api/students
router.put('/:id', updateStudent);       // PUT  /api/students/:id
router.delete('/:id', deleteStudent);    // DELETE /api/students/:id

module.exports = router;
Controller — The Heart of the API

Writing the CRUD Controller

What is a controller?

A controller is the file that contains all the actual logic. When a request arrives, the route sends it to the right controller function. The controller then talks to MongoDB (using our Student model) and sends a response back. Controllers keep your route file clean and your logic organised.

Create backend/controllers/studentController.js:

backend/controllers/studentController.js
const Student = require('../models/Student');

// ─── Helper: handle errors consistently ───────────────────
const handleError = (res, error) => {
  res.status(500).json({ message: 'Server error', error: error.message });
};

// ─── READ ALL ─────────────────────────────────────────────
// GET /api/students — returns all students
const getAllStudents = async (req, res) => {
  try {
    const students = await Student.find(); // get all from MongoDB
    res.status(200).json(students);
  } catch (error) {
    handleError(res, error);
  }
};

// ─── READ ONE ─────────────────────────────────────────────
// GET /api/students/:id — returns one student
const getStudentById = async (req, res) => {
  try {
    const student = await Student.findById(req.params.id);

    // If student not found, return 404
    if (!student) {
      return res.status(404).json({ message: 'Student not found' });
    }

    res.status(200).json(student);
  } catch (error) {
    handleError(res, error);
  }
};

// ─── CREATE ───────────────────────────────────────────────
// POST /api/students — creates a new student
const createStudent = async (req, res) => {
  try {
    // Get data from request body (what React sends us)
    const { name, email, course, age } = req.body;

    // Create a new student document
    const student = new Student({ name, email, course, age });

    // Save it to MongoDB
    await student.save();

    // Return 201 Created with the new student
    res.status(201).json(student);
  } catch (error) {
    handleError(res, error);
  }
};

// ─── UPDATE ───────────────────────────────────────────────
// PUT /api/students/:id — updates existing student
const updateStudent = async (req, res) => {
  try {
    const student = await Student.findByIdAndUpdate(
      req.params.id,    // which student to update
      req.body,         // new data to apply
      { new: true }    // return the UPDATED version
    );

    if (!student) {
      return res.status(404).json({ message: 'Student not found' });
    }

    res.status(200).json(student);
  } catch (error) {
    handleError(res, error);
  }
};

// ─── DELETE ───────────────────────────────────────────────
// DELETE /api/students/:id — removes a student
const deleteStudent = async (req, res) => {
  try {
    const student = await Student.findByIdAndDelete(req.params.id);

    if (!student) {
      return res.status(404).json({ message: 'Student not found' });
    }

    res.status(200).json({ message: 'Student deleted successfully' });
  } catch (error) {
    handleError(res, error);
  }
};

// Export all functions so routes can use them
module.exports = {
  getAllStudents,
  getStudentById,
  createStudent,
  updateStudent,
  deleteStudent,
};
HTTP Status Codes

Understanding Status Codes

Status codes = the server's way of saying how it went

Every API response includes a status code — a 3-digit number that tells the client whether the request succeeded or failed. Think of it like a delivery notification: "Delivered ✅", "Address not found ❌", "Our system crashed 🔥".

200
OK
Request worked. Data returned.
201
Created
New item created successfully.
400
Bad Request
Request data is wrong or missing.
404
Not Found
ID doesn't match any record.
500
Server Error
Something broke on the server side.

API Testing

Testing With Postman — Step by Step

What is Postman?

Postman is a free app that lets you send HTTP requests to your API without needing a frontend. It's like a fake frontend — you can click "Send" and see exactly what your API returns. Download it free from postman.com.

POST Create a new student
  1. Open Postman → click New Request
  2. Change method to POST
  3. Enter URL: http://localhost:5000/api/students
  4. Click Body → select raw → change to JSON
  5. Paste: {"name":"Test Student","email":"test@uni.lk","course":"IT"}
  6. Click Send → you should see 201 Created ✅
GET Get all students
  1. Method: GET
  2. URL: http://localhost:5000/api/students
  3. Click Send → you see an array of all students ✅
PUT Update a student
  1. Copy a student's _id from the GET response
  2. Method: PUT
  3. URL: http://localhost:5000/api/students/PASTE_ID_HERE
  4. Body (raw JSON): {"name":"Updated Name","course":"Computer Science"}
  5. Click Send → see the updated student returned ✅
DELETE Delete a student
  1. Method: DELETE
  2. URL: http://localhost:5000/api/students/PASTE_ID_HERE
  3. No body needed — just click Send
  4. See: {"message":"Student deleted successfully"} ✅

Software Testing

Automated Tests With Jest & Supertest

Here are the 5 key tests that verify every API route works correctly:

backend/tests/student.test.js
const request = require('supertest');
const app = require('../server');

let studentId; // store ID for update/delete tests

// Test 1: Create a student
test('POST /api/students — creates a student', async () => {
  const res = await request(app)
    .post('/api/students')
    .send({ name: 'Test Student', email: 't@t.lk', course: 'IT' });

  expect(res.statusCode).toBe(201);
  expect(res.body.name).toBe('Test Student');
  studentId = res.body._id; // save for later tests
});

// Test 2: Get all students
test('GET /api/students — returns array', async () => {
  const res = await request(app).get('/api/students');
  expect(res.statusCode).toBe(200);
  expect(Array.isArray(res.body)).toBe(true);
});

// Test 3: Get one student
test('GET /api/students/:id — returns one student', async () => {
  const res = await request(app).get(`/api/students/${studentId}`);
  expect(res.statusCode).toBe(200);
  expect(res.body._id).toBe(studentId);
});

// Test 4: Update a student
test('PUT /api/students/:id — updates student name', async () => {
  const res = await request(app)
    .put(`/api/students/${studentId}`)
    .send({ name: 'Updated Name' });
  expect(res.statusCode).toBe(200);
  expect(res.body.name).toBe('Updated Name');
});

// Test 5: Delete a student
test('DELETE /api/students/:id — removes student', async () => {
  const res = await request(app).delete(`/api/students/${studentId}`);
  expect(res.statusCode).toBe(200);
  expect(res.body.message).toBe('Student deleted successfully');
});

Why write tests?

Tests catch bugs automatically. Instead of manually testing every route in Postman every time you make a change, Jest does it for you in seconds. If a test fails, you know exactly which route broke.

Clean Code

Clean Code Tips for This Module

  • Always use async/await instead of .then().catch() — it's easier to read
  • Always wrap async code in try/catch — never let errors crash your server
  • Always check if a document exists before returning it — send 404 if not found
  • Use the handleError helper to avoid repeating the same error code everywhere
  • Keep your controller functions short and focused — one function, one job
  • Add a comment above each function explaining what route it handles
The golden rule of error handling

Your server should never crash because of bad input from the user. Always wrap database calls in try/catch and always return a meaningful error message with the right status code.
