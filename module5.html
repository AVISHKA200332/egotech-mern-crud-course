REST in Simple Terms

A REST API treats your data as resources. In this course the resource is student, so the routes are named around students and the HTTP method describes the action.

Resource name
Use nouns like /students, not verbs like /getStudents.
HTTP method
Use GET, POST, PUT, and DELETE for predictable behavior.

Endpoint Design

MethodRoutePurpose
GET/api/studentsReturn all students
GET/api/students/:idReturn one student by id
POST/api/studentsCreate a new student
PUT/api/students/:idUpdate a student
DELETE/api/students/:idDelete a student

Status Codes and Response Shape

Always return consistent JSON so the frontend knows what to expect. A clear response format reduces bugs and makes debugging faster.

Response exampleJSON
{
	"success": true,
	"message": "Student created successfully",
	"student": {
		"_id": "665...",
		"name": "Asha",
		"email": "asha@example.com"
	}
}

Test with Postman

Postman is where you confirm the API works before React touches it. If it fails in Postman, fix the backend first.

Send a POST
Pick JSON body, set name, email, age, and course.
Verify response
Check status codes, response body, and database changes.
Test delete
Send a DELETE request with the student id.
Test update
Use PUT with the id and the new JSON payload.
