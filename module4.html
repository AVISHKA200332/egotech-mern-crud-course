Concept

What is MongoDB?

Think of MongoDB like a notebook

A traditional database stores data in rigid tables with rows and columns — like a spreadsheet. MongoDB stores data as flexible documents — like pages in a notebook. Each page (document) can look slightly different, which makes it very flexible and easy to work with when your data changes over time.

In MongoDB, data is organized like this:

🏢
Database
The whole building
e.g. studentdb
📁
Collection
A folder/group of similar items
e.g. students
📄
Document
One record (one student)
looks like JSON

A document in MongoDB looks exactly like JSON you already know from JavaScript:

One document in the students collection
{
  "_id": "64a1b2c3d4e5f6789abc1234",  // auto-generated unique ID
  "name": "Kaveesha Jagoda",
  "email": "kaveesha@university.lk",
  "course": "Information Technology",
  "age": 21,
  "isActive": true,
  "createdAt": "2024-01-15T08:30:00.000Z"
}
Comparison

SQL vs NoSQL — What's the Difference?

Don't worry — you don't need to know SQL for this course

But understanding the difference helps you know why we chose MongoDB. SQL databases store data like strict spreadsheets. MongoDB (NoSQL) stores data like flexible JSON objects. For JavaScript apps, MongoDB feels very natural because you're already writing JSON everywhere.

SQL (e.g. MySQL) NoSQL (MongoDB)
Stores data in tables with fixed columnsStores data as flexible JSON documents
Every row must match the same structureEach document can have different fields
Good for very structured data (e.g. banking)Good for flexible, changing data (e.g. apps)
Uses SQL query languageUses JavaScript-like queries
Examples: MySQL, PostgreSQLExamples: MongoDB, Firebase
Concept

What is Mongoose?

Mongoose = a translator between Node.js and MongoDB

MongoDB understands its own language. Mongoose is a library that lets you talk to MongoDB using normal JavaScript. It also lets you define a schema — a set of rules that says what each document must look like (required fields, data types, validation).

  • Mongoose lets you define schemas — rules for your data shape
  • Mongoose gives you easy methods like .find(), .save(), .delete()
  • Mongoose automatically validates data before saving it
  • Mongoose adds timestamps (createdAt, updatedAt) automatically
Setup

Connect Express to MongoDB

First, create your .env file in the backend/ folder to store your secret connection string:

backend/.env
PORT=5000
MONGO_URI=mongodb+srv://yourUsername:yourPassword@cluster0.xxxxx.mongodb.net/studentdb
Never share your .env file!

The .env file contains your database password. Never commit it to GitHub. Make sure .env is listed in your .gitignore file.

Now create backend/config/db.js to handle the connection:

backend/config/db.js
const mongoose = require('mongoose');

const connectDB = async () => {
  try {
    // Connect to MongoDB using the URI from .env
    await mongoose.connect(process.env.MONGO_URI);
    console.log('✅ MongoDB Connected!');
  } catch (error) {
    // If connection fails, print the error and stop the server
    console.error('❌ MongoDB connection failed:', error.message);
    process.exit(1); // exit with failure
  }
};

module.exports = connectDB;

Then call connectDB() in your server.js:

backend/server.js — add these lines
const connectDB = require('./config/db');

// Call connectDB when the server starts
connectDB();

Creating the Schema & Model

Schema vs Model — what's the difference?

A schema is the blueprint — it defines the rules (field names, types, required or not). A model is the actual tool you use in your code — it reads the schema and gives you methods to create, read, update, and delete documents. You define the schema once and create the model from it.

Create the file backend/models/Student.js:

backend/models/Student.js
const mongoose = require('mongoose');

// Step 1 — Define the schema (rules for our data)
const studentSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: [true, 'Name is required'],  // must be provided
      trim: true,                                // removes extra spaces
    },
    email: {
      type: String,
      required: [true, 'Email is required'],
      unique: true,    // no two students can have the same email
      lowercase: true, // auto-converts to lowercase before saving
    },
    course: {
      type: String,
      required: [true, 'Course is required'],
    },
    age: {
      type: Number,
      min: [16, 'Age must be at least 16'], // validation
      max: [100, 'Age cannot exceed 100'],
    },
    isActive: {
      type: Boolean,
      default: true, // auto set to true if not provided
    },
  },
  {
    timestamps: true, // auto-adds createdAt and updatedAt
  }
);

// Step 2 — Create the model from the schema
// 'Student' becomes the collection name 'students' in MongoDB
const Student = mongoose.model('Student', studentSchema);

module.exports = Student;
Mongoose Queries

Useful Mongoose Queries

These are the most common operations you will use. Each one talks to MongoDB for you.

GET — Find all students
const students = await Student.find();
// Returns an array of ALL student documents
GET — Find one student by ID
const student = await Student.findById(id);
// Returns ONE student matching the ID, or null if not found
POST — Create a new student
const student = new Student({ name, email, course });
await student.save(); // saves to MongoDB
PUT — Update a student
const student = await Student.findByIdAndUpdate(
  id,
  { name, email, course }, // new values
  { new: true }           // returns the UPDATED document
);
DELETE — Remove a student
await Student.findByIdAndDelete(id);
// Permanently removes the student from MongoDB

Software Testing

Testing the Student Model

We test the model to make sure validation rules work correctly. A good test checks both the happy path (valid data) and the sad path (invalid/missing data).

backend/tests/student.test.js
const Student = require('../models/Student');

// Test 1: Valid student should pass validation
test('creates a valid student', () => {
  const student = new Student({
    name: 'Kaveesha',
    email: 'k@uni.lk',
    course: 'IT',
  });
  const err = student.validateSync(); // check for errors
  expect(err).toBeUndefined();           // no errors = pass
});

// Test 2: Missing name should fail
test('fails without a name', () => {
  const student = new Student({
    email: 'k@uni.lk',
    course: 'IT',
  });
  const err = student.validateSync();
  expect(err.errors.name).toBeDefined(); // name error should exist
});

// Test 3: isActive should default to true
test('isActive defaults to true', () => {
  const student = new Student({
    name: 'Nisal', email: 'n@uni.lk', course: 'CS',
  });
  expect(student.isActive).toBe(true);
});
