Final Project Goal

By the end of this course, your app should let a user add, view, edit, and delete student records through a clean React interface backed by an Express API and MongoDB Atlas.

Frontend
Form, list, buttons, feedback states, and responsive layout.
Backend
Routes, controllers, validation, and JSON responses.

Best Practices

Keep components small
One component should do one thing well.
Use clear names
Name functions and files after what they do.
Protect secrets
Store URLs and passwords in environment variables.
Handle errors
Show useful messages instead of silent failures.
Keep state in sync
Refresh the UI after save, edit, and delete actions.
Design for mobile
Check that forms and tables still work on small screens.

Shared Responsibilities

In a real project, frontend, backend, and database work often happen in parallel. Clear ownership keeps the app moving without people stepping on each other.

AreaMain ResponsibilityExample Tasks
FrontendUser interface and user experienceForms, lists, routing, validation messages
BackendAPI logic and server rulesRoutes, controllers, CORS, status codes
DatabaseData structure and persistenceSchema design, queries, validation, Atlas access

Completion Checklist

  • 1
    The app loads without console errors.
  • 2
    Students can be created, edited, listed, and deleted.
  • 3
    The frontend talks to the backend in both local and deployed environments.
  • 4
    Secrets are stored in environment variables, not in source code.
  • 5
    The project has a clear README and can be handed to another developer.
