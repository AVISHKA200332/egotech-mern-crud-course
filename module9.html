Deployment Map

The production version usually has three parts. The frontend is a static web app, the backend is a Node server, and the database stays in MongoDB Atlas.

Frontend
React build on Vercel or Netlify.
Backend
Express API on Render or Railway.
Database
MongoDB Atlas with a restricted production user.

Deploy the Backend

Push the backend code to GitHub first. Then create a new web service on your hosting platform and point it to the repository branch that contains the API.

Production server entryJS
const PORT = process.env.PORT || 5000;

app.listen(PORT, () => {
	console.log(`Server running on port ${PORT}`);
});
Typical backend settings: build command is usually empty for Express, start command is node server.js, and the service must expose the port from process.env.PORT.

Deploy the Frontend

React projects are usually built before deployment. The deploy platform serves the static production files and points the app at the production API URL.

frontend buildCLI
npm run build
npm run preview
For production, replace the localhost API address with the hosted backend URL in VITE_API_URL or the equivalent frontend environment variable.

Database and Environment Variables

Production deployments depend on correct environment variables. Store secrets in the host settings, not in GitHub commits.

backend/.envENV
PORT=5000
MONGO_URI=mongodb+srv://username:password@cluster0.example.mongodb.net/studentDB
CORS_ORIGIN=https://your-frontend.vercel.app
Never commit secrets
Use host dashboard env vars instead of source control.
Allow the right origin
CORS should match the deployed frontend domain.

Deployment Troubleshooting

App returns 502 or 500
Check logs, port binding, and missing env vars.
Frontend cannot reach API
Verify production CORS and the API URL.
Database connection fails
Confirm Atlas IP access and username/password.
Deploy build missing
Make sure the correct root folder is selected.
