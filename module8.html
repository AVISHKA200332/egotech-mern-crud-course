CRUD Flow Overview

CRUD means Create, Read, Update, and Delete. Each action maps to a specific HTTP method and a single job in the app.

Create
POST a new student.
Read
GET the student list.
Update
PUT changed values.
Delete
Remove one record.

Create Students

The form starts in create mode. When the user submits it, send a POST request to the API and then clear the form.

create exampleJSX
const handleSave = async () => {
	try {
		const response = await api.post('/students', formData);
		setStudents([response.data.student, ...students]);
		setMessage('Student created successfully.');
		setFormData(initialForm);
	} catch (err) {
		setMessage('Could not create student.');
	}
};

Read and Display Students

Reading data happens on page load and after each successful action. The list should update without reloading the browser.

read exampleJSX
{students.length === 0 ? (
	<div className="alert alert-light border text-center">
		No students yet. Add the first record.
	</div>
) : (
	students.map((student) => (
		<StudentCard key={student._id} student={student} onEdit={handleEdit} onDelete={handleDelete} />
	))
)}

Update Students

Editing is usually done by loading the selected record into the form, switching the button label, and sending a PUT request.

update exampleJSX
const handleEdit = (student) => {
	setEditingId(student._id);
	setFormData({
		name: student.name,
		email: student.email,
		age: student.age,
		course: student.course,
	});
};

const handleUpdate = async () => {
	await api.put(`/students/${editingId}`, formData);
};

Delete Students

Deleting should always require a clear action and usually a confirmation prompt. After the API responds, remove the record from state.

delete exampleJSX
const handleDelete = async (id) => {
	const confirmDelete = window.confirm('Delete this student?');
	if (!confirmDelete) return;

	await api.delete(`/students/${id}`);
	setStudents(students.filter((student) => student._id !== id));
};

UI Feedback and Error Handling

Good CRUD screens always tell the user what happened. Use success messages, loading text, and short error notices instead of silent failures.

Success
Show when a save or delete finishes correctly.
Error
Show when the API request fails or validation is missing.
Loading
Show while waiting for the first fetch.
Refresh
Refetch or update state after each action.
